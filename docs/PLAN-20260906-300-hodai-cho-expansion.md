# 放題帖を02_devへ新規実装する（v1.1土台＋宴会食放拡張）

## Problem Statement

食べ放題に行くとき「いくら・何分・どの駅」が一度に見えない。既存グルメサイトは食べ放題以外が混ざり、制限時間で切れない。放題帖（要求定義書 v1.1）は東京・神奈川の食べ放題だけを料金・制限時間・駅で切る条件帳として as-built を定義した。本PLANは v1.1 を土台に、カタログ拡充（新規開拓・宴会食放まで）と予約リンクのみを足して `02_dev/hodai-cho` に新規実装するための設計である。

## §1 リポジトリ・運用・技術

- 新規リポジトリ: `02_dev/hodai-cho`（localStorageキー `hodai-cho` と同名）
- 技術: Vite + React + TypeScript + Tailwind。サーバDBなし・カタログ同梱。フィルタはクライアント即時（サーバ往復なし）
- DBなしで成り立つ理由: カタログは同梱JSONで初回後はメモリ内フィルタ。外部通信は地図・予約の外部リンクのみ。数百店でも数百KB級。更新は再配布
- 拡張の縫い目: カタログ取得を Repository 抽象に隔離（今は同梱JSON、将来API/CMSへ差し替え可、画面変更なし）。スキーマ version、ID採番規則、エリア/ジャンル taxonomy を拡張可能に
- PLAN運用: 正本は本ファイル。product 側へ参照コピーを置く。Ticket は Department 扱いで起票
- UI前提: `lang="ja"`、ダーク固定（暖黒/象牙/石色/朱）、見出し明朝・本文ゴシック、タップ面44px以上、prefers-reduced-motion 対応、ページ全体の横スクロールなし、最大幅モバイルカラム中央寄せ

## §2 カタログ拡張

- 新区分「宴会食放」をジャンルに追加（既存6: 焼肉/しゃぶしゃぶ/寿司/スイーツ/ピザ/串揚げ＋新1）。副ジャンル検索を踏襲
- 採否: 食べ放題が来店目的になりうる宴会コースまで可。飲み放題本体・カラオケは除外
- データ差分（最小）: 店舗に `reservationUrl`（任意）と `reservationAffiliateUrl`（任意。あれば予約CTAに使い、なければ `reservationUrl` に倒す）、コースに `banquet` 旗（任意）を追加。価格・分数・駅・徒歩・編集ピック等の必須は v1.1 維持
- 追加店リストは本PLAN時点では未確定。実装着手前に候補リスト（新規開拓・宴会食放含む）の確定を入力条件とする
- 運用: 人手精査のみ、未精査は掲載しない。2026年時点の公開情報目安、土日加算・締切は注記、共通免責を維持
- 正確さのために落とす/注記する扱い（温野菜ランチ、ゆず庵一部店のランチなし、都心価格、シェーキーズ店差）は v1.1 §10.5 を踏襲し、新規店にも適用

## §3 画面・機能差分

- 探す（`/`）: ジャンルチップに宴会食放追加。都県/エリア/フリーワード/時間帯/分数/上限/並び・件数・0件案内・リセット（都県維持）は v1.1 維持。詳細条件はシート
- 一覧カード: 宴会食放用の料理静物写真1点追加（人物なし・実写なし）。ランチ/ディナー最安と分数、ハイライト先頭、保存ボタン（遷移と独立）
- 詳細（`/r/:id`）: D-01〜D-09 維持、D-10 予約リンク（外部・別タブ・在庫連動なし）を追加。未知IDは「店が見つからない」＋探す導線
- 保存（`/saved`）: localStorage のみ、フィルタ非永続、保存順。クラウド同期なし
- ナビ: 探す/保存の2タブのみ。今夜タブなし

## Architecture / Components / Data flow

- 静的SPA: `catalog`（同梱JSON）→ `repository`（抽象）→ `filter`（メモリ内即時）→ `list/detail/saved` 画面。`favorites` は localStorage adapter のみ
- コンポーネント: 条件シート、結果リスト、カード、詳細コース表、類似店（同都県の同チェーン→同エリア他チェーン、最大4件）、空状態
- データフロー: 条件変更は再レンダーのみ。永続化するのはお気に入りIDのみ。フィルタ条件は永続化しない
- エラー処理: 0件は理由＋緩和案、未知IDは専用表示、外部リンク失敗はブラウザに委譲（アプリ内で握らない）

## Testing

- 条件組合せ（都県×エリア×ジャンル×時間帯×分数×上限×並び）、宴会食放の絞り込み、ランチなし店の消え方、無制限/90分以内/120分以内の判定
- 保存の追加・解除・再訪残存、未知ID、0件案内、地図・予約リンクの別タブ遷移、a11y（aria-pressed/label、44px、lang="ja"）

## 受け入れ条件

v1.1 §13 に次を加えて満たすこと。

- ジャンル「宴会食放」で該当店だけが残り、飲み放題居酒屋・カラオケが出ない
- 詳細に予約リンク（外部）が表示され、アプリ内で決済・在庫確認が発生しない
- 東京/神奈川の切替・並び・保存・免責表示が v1.1 通りに動く
